المطلوب منك:

ابدأ مباشرة بتحليل المشروع وتأكيد استيعابك للملفات المتاحة دون إضاعة الوقت.





فكيرة ممتازة وتطبيقها العملي شائع ومطلوب جداً (ويُعرف تقنياً بـ Calculator Vault).
لضمان تقديم التطبيق بأعلى مستوى من الاحترافية والأمان، تم رسم الحدود الفنية والتصميمية للفكرة بناءً على متطلباتك:
1. الآلية البرمجية والمنطق (Application Logic)
 * الواجهة الظاهرة (The Cover):
   * حاسبة تظهر وتعمل بنسبة 100% مثل حاسبة Samsung الرسمية (عمليات جمع، ضرب، طرح، نسبة مئوية، مسح C، وحفظ في الذاكرة).
   * عند كتابة أي معادلة عادية والضغط على = تقوم الحاسبة بالعملية الحسابية الطبيعية دون إظهار أي مؤشر على وجود نظام خفي.
 * بوابة الدخول السرية (Secret Trigger):
   * عند إدخال رمز المرور الافتراضي 280126 ثم الضغط على زر =، يتم اعتراض الإدخال (Intercept) قبل التقييم الحسابي، وتتغير الواجهة فوراً للدخول إلى الخزنة.
 * إدارة رمز المرور (PIN Management):
   * إمكانية تغيير الرمز من داخل إعدادات الخزنة في أي وقت.
   * حفظ الرمز المشفّر محلياً باستخدام Keychain (لأجهزة iOS) أو EncryptedSharedPreferences / Keystore (لأجهزة Android).
2. التخزين المحلي والأمان (Local Storage & Security)
بما أن الشرط الأساسي هو عدم الاستعانة بأي خوادم سحابية، يجب الاعتماد على الهيكلية التالية:
 * التشفير المحلي (Local Encryption):
   * تشفير الملفات والصور باستخدام خوارزمية AES-256 قبل حفظها في ذاكرة الجهاز الداخلية.
   * عدم حفظ الملفات في المعرض العام (Gallery/DCIM)، بل في المجلد الخاص بالتطبيق (Internal App Storage) لضمان عدم ظهورها في أي تطبيق آخر.
 * الحماية من الاسترجاع والـ Security Hardening:
   * Anti-Screenshot / Anti-Screen Recording: منع أخذ لقطات شاشة أو تسجيل الشاشة أثناء التواجد داخل الخزنة.
   * Biometric Backup (اختياري): تفعيل البصمة (Fingerprint / Face ID) للدخول السريع بعد تفعيل الرمز لأول مرة.
   * Auto-Lock: إغلاق الخزنة فوراً والعودة لشاشة الحاسبة عند الخروج من التطبيق أو وضعه في الخلفية.
3. تجربة المستخدم داخل الخزنة (Vault Features)
عند تجاوز شاشة الحاسبة، يتم فتح واجهة الخزنة المستقلة والتي تحتوي على:
 * تقسيم المحتوى:
   * قسم الصور والحيّز المرئي (مع مستعرض صور مدمج يدعم التكبير/التصغير).
   * قسم للفيديوهات (مع مشغل ميديا محلي يدعم التشفير أثناء التشغيل).
   * قسم المستندات والملفات العامة (PDF، Word، إلخ).
 * خيارات الاستيراد والتصدير (Import/Export):
   * إمكانية استيراد الملفات من الجهاز ثم حذف الأصل تلقائياً (بعد أخذ إذن المستخدم).
   * إمكانية فك التشفير واستعادة الملف إلى المعرض العام في أي وقت.
4. حزم التطوير المقترحة (Tech Stack)
إذا كنت تخطط لبرمجته (سواء بلغة Flutter أو React Native أو Native Android/iOS):
| العنصر | التقنية المقترحة |
|---|---|
| واجهة المستخدم | Flutter (لتصميم واجهة حاسبة تشبه Samsung بسهولة لجميع المنصات) |
| قاعدة البيانات المحلية | Hive أو SQLite (لتخزين بيانات هيكل المجلدات والأسماء) |
| تشفير الملفات | encrypt package (خوارزمية AES-256) |
| الحماية | flutter_windowmanager (لمنع لقطات الشاشة في أندرويد) |

هذا المخطط الهيكلي (Wireframe) وتوزيع العناصر للتطبيقيْن المتداخلين: واجهة الحاسبة الظاهرة وواجهة الخزنة السرية.

تفاصيل العناصر والوظائف:
 * Header (الشريط العلوي):
   * زر الخروج السريع (🚪): قفل الخزنة فوراً والعودة لشاشة الحاسبة ومسح الذاكرة المؤقتة (Cache).
   * زر الإعدادات (⚙️): يحتوي على:
     * تغيير رمز الدخول (الافتراضي 280126).
     * تفعيل/إلغاء البصمة (Biometrics).
     * خيار "الرمز المزيف" (Decoy PIN) الذي يفتح خزنة فارغة عند الإكراه.
 * Main Grid (أقسام التخزين):
   * شبكة مربعة تنظم الملفات حسب النوع.
   * كل قسم يفتح معرضاً خاصاً (Gallery View) مع إمكانية عرض المصغرات المشفرة (Encrypted Thumbnails).
 * FAB - Floating Action Button (زر الإضافة +):
   * عند الضغط عليه تظهر قائمة خيارات:
     * استيراد صور/فيديو: فتح المعرض لاختيار الملفات ونقلها للتطبيق.
     * التقاط مباشر: فتح الكاميرا وتخزين الصورة مباشرة في الخزنة دون مرورها بمعرض الجهاز.
     * استيراد ملفات: فتح متصفح ملفات النظام.
     * ملاحظة: بعد الاستيراد، يظهر خيار تفاعلي: "هل تريد حذف الأصل من جهازك للحفاظ على الخصوصية؟".




تعديلات وتطوير
إيه، الآن الفكرة تستحق أن نتعامل معها كـ منتج خصوصية حقيقي وليس مجرد “حاسبة تخبّي صور”. راجعت التصميم الحالي وربطته بمعايير OWASP للأمان المحمول، وأرى أن أفضل نسخة للمشروع أبسط ظاهريًا بكثير، لكن أقوى تحت الغطاء. معيار OWASP MASVS نفسه يغطي التخزين والتشفير والمصادقة والتعامل مع المنصة ومقاومة العبث والخصوصية، وهذا بالضبط خط الأساس المناسب لنا. 

رؤيتي النهائية للتطبيق

أريده عند فتحه يبدو حاسبة ممتازة فعلًا. ليس واجهة مزيفة رخيصة تجعل أي شخص يشك فيها بعد 12 ثانية.

الشاشة الرئيسية تكون نظيفة جدًا وقريبة من تجربة الحاسبات الأصلية، وتدعم الحسابات الأساسية، الأقواس، النسبة المئوية، سجل العمليات، الوضع الداكن والفاتح، ونسخ النتائج. ولا يظهر فيها أي شيء باسم Vault أو Private أو Lock.

أما الدخول الخاص فلا أجعله قائمًا على 280126 ثابت داخل الكود. هذا الرقم يصلح فقط كبداية أثناء التطوير. عند أول إعداد، المستخدم ينشئ رمزه بنفسه.

PIN → = → تحقق محلي آمن → فتح الخزنة.

والإدخال الخاطئ يتصرف كعملية حاسبة طبيعية، بدون رسالة “PIN خاطئ”. هذا يحافظ على بساطة الغطاء.

أكبر خطأ يمكن أن نرتكبه هو:

        ↓

        ↓
Secure Enclave / Keychain
أو

        ↓
Wrap / Protect
        ↓
File Encryption Keys
        ↓

        ↓
Encrypted Files

كل ملف يحصل على مفتاح/Nonce مناسب، ويكون لدينا metadata مشفر، وليس مجرد ملفات اسمها IMG_123.enc.

OWASP يوصي باستخدام مخازن المفاتيح الخاصة بالنظام، ويفضل التخزين المدعوم بالعتاد عندما يتوفر. كما يوضح أن وضع مفتاح التشفير داخل التطبيق أو بجانب الملفات المشفرة تصميم غير آمن. 

والـPIN نفسه لا نخزنه كنص إطلاقًا.

نحمي:

الملف الأصلي + المصغرات + أسماء الملفات + metadata الحساسة + الملفات المؤقتة + حالة المشغل + نتائج البحث + النسخ الاحتياطية.

OWASP يحذر تحديدًا من التسريب عبر caches والملفات المؤقتة والنسخ الاحتياطية، وليس فقط مكان تخزين الملف الأساسي.

🔑 الدخول أريد له مستويين فقط

حتى لا يتحول التطبيق إلى لوحة قيادة مفاعل نووي.

PIN أساسي: للدخول الطبيعي.

Biometric Unlock: اختياري بعد أن يفعله المستخدم بنفسه.

Face ID والبصمة لا يكونان بديلًا عن وجود مفتاح آمن، وإنما طريقة للسماح باستخدامه.

OWASP يوصي باستخدام آليات النظام للمصادقة البيومترية، مع fallback مناسب، كما يشدد على إعادة المصادقة للعمليات الحساسة. 

مثلاً تغيير PIN أو تصدير 500 صورة دفعة واحدة يمكن أن يطلب إعادة المصادقة.

لكن لن أجعلها مفعلة افتراضيًا. معظم المستخدمين لا يحتاجون هذا التعقيد.

والأهم: Security Modes

بدل إجبار الجميع على نفس السلوك، أضيف ثلاثة Profiles داخل الإعدادات، من دون تغيير التشفير الأساسي:

الوضع	السلوك
Balanced	قفل عند الخلفية + Biometrics
Strict	قفل فوري + حماية إضافية + تنظيف أسرع للذاكرة المؤقتة
Custom	المستخدم يحدد كل شيء

لا أضع وضعًا “ضعيف الأمان”، لأن خيارًا اسمه Convenience ينتهي عادة بأن يصبح “احتفظ بكل شيء مفتوحًا للأبد”. 🙃

معيار القبول الأمني

قبل أن أسمي النسخة Stable، أجعل الاختبارات مبنية على OWASP MASVS⁠￼ وOWASP MASTG⁠￼، خصوصًا Storage وCrypto وAuth وPlatform وPrivacy وResilience. OWASP يعتبر MASVS معيارًا صناعيًا لتقييم أمان تطبيقات الجوال، وهو مرجع أفضل بكثير من أن نكتب “AES-256 🔒” في README ونعلن النصر. 

والتغيير الأكبر الذي أوصي به للمشروع: لا نبني “تطبيق حاسبة يخفي ملفات”. نبني Private Offline Vault قويًا جدًا، والحاسبة مجرد واجهته الطبيعية والبسيطة. بهذا التفكير تتغير جودة المعمارية كلها من البداية.
